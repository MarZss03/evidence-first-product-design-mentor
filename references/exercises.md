# Exercise library

Select one exercise that targets the learner's present reasoning gap. Adapt the domain and timebox; do not assign a collection by default.

## 10-minute exercises

### Evidence sort

Give or collect ten statements from the project. Ask the learner to label each Observed, Reported, Assumed, Inferred, or Unknown, then identify the most dangerous mislabeled claim.

### Task sentence

Complete: “When ___, this user needs to ___ so that ___, while ___ constrains the solution.” Remove any UI component from the sentence.

### Hierarchy check

List the five things a user can notice or do on a screen. Rank them by task importance, then compare that order with their visual prominence.

### Failure flip

Take the happy path and change one condition: no data, slow network, denied permission, conflicting update, low AI confidence, or destructive mistake. Describe how the user recovers.

## 30-minute exercises

### Three-direction sketch

Create three structurally different approaches to the same task. For each, write the user benefit, operational cost, and assumption that could invalidate it.

### Flow compression

Map the current flow as actions and system responses. Mark repeated input, waiting, context switches, hidden dependencies, and irreversible steps. Remove one step only when the system can safely carry its responsibility.

### Critique-to-test

Choose one suspected usability issue. Turn it into a testable task, success signal, observation plan, and disconfirming result.

### Edge-state matrix

For one key component or flow, cover normal, loading, empty, error, permission, stale/conflict, success, and recovery. Keep only states relevant to the product.

## 60-minute exercises

### Evidence-to-decision chain

Build a table with evidence, interpretation, design implication, alternative, decision, risk, and validation. Audit every unsupported jump.

### Mini usability session

Write one neutral task, define completion evidence, run it with one participant or realistic walkthrough, record behavior without coaching, then revise one material issue.

### Case-study spine

Write one sentence each for problem, role, constraint, evidence, changed decision, validation, result, and limitation. Remove any sentence whose claim cannot be sourced.

## Transfer checks

After feedback, ask the learner to apply the principle to a different screen, audience, or constraint. A correct restatement is helpful; a correct transfer is stronger evidence of learning.
